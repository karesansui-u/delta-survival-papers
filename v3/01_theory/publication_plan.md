公開構成計画
— 内部文書構成と公開論文単位の分離 —

要旨

本メモは、v3 の内部文書構成と、公開時の論文単位を分けて整理するための編集メモである。新しい理論主張、実験、支持判定を追加するものではない。現時点の正本は `02_core.md` であり、本メモはその読者導線に合わせて、公開第一稿と公開第二稿の候補構成を管理する。


1. 現在の内部構成

現在の内部構成は、執筆・検証・更新のために分かれている。

| 内部文書 | 役割 |
|---|---|
| `00_map.md` | 全体地図、読み順、主張強度、証拠状態の位置づけ |
| `01_overview.md` | 統合版の入口、主理論と観測レイヤーの導線 |
| `02_core.md` | 現在の正本。構造維持問題、最小核、収支原理、二つの観測レイヤーの読者向け中心 |
| `10_paper1_minimal_form.md` | 最小形式。縮小、対数比の一意性、望遠鏡積の基礎分冊 |
| `11_paper2_balance_principle.md` | 収支原理。消耗、回復、純消耗量、回復込み指数核の基礎分冊 |
| `02_foundations/27_specification_fixed_operational_theorems.md` | 仕様固定レイヤーの操作的定理アンカー |
| `03_domains/` | 個別ドメイン・プロファイル |
| `05_evidence/` | 支持、非支持、無効実行、外部再実行、証拠台帳 |

この内部構成は、公開論文の分割をそのまま意味しない。内部では細かく分け、公開時には証拠の種類と読者導線に応じて束ねる。


2. 公開第一稿の候補

公開第一稿は、基礎理論と仕様固定で閉じる硬い部分をまとめる候補である。

候補タイトルは、たとえば次のように置ける。

> 構造持続理論: 基礎と仕様固定アンカー

候補章立て:

1. 問い: 資源不足だけでなく、維持可能領域の縮小を見る
2. 構造維持問題: 基体 \(X\)、維持条件 \(G\)、維持可能領域 \(V\)、ものさし \(m\)
3. 縮小の尺度: 対数比の一意性
4. 収縮モード: \(L\) と \(m(V^{(n)})=m(V^{(0)})e^{-L_n}\)
5. 回復込み収支: \(d_t,r_t,b_t,B_n\)
6. 回復の有限集合例: \(100\to40\to80\) による \(d_t,r_t,b_t\) の読解
7. 構造持続ポテンシャル: \(S=Me^{-L}\) と \(S=Me^{-B}\)
8. 仕様固定レイヤー: 何が仕様から直接固定できるか
9. 操作的アンカー: 有限 CSP、二元消失通信路上の線形符号、有限グラフ
10. Lean 形式化の範囲: 何を検査し、何を検査していないか
11. 主張境界: Shannon 容量定理、鋭いしきい値定理、物理的エントロピー生産との非同一視

公開第一稿では、推定レイヤーの詳細な支持 / 非支持 / 失敗台帳は主役にしない。必要な場合は、第二稿への導線として短く触れる。


3. 公開第二稿の候補

公開第二稿は、直接 \(V,m\) を数えられない現実系で、観測・推定指標がどこまで働くかを扱う候補である。

候補タイトルは、たとえば次のように置ける。

> 構造持続理論: 推定レイヤーと凍結検証

候補章立て:

1. なぜ推定レイヤーが必要か
2. 観測・推定指標と、法則側座標 \(L,B\) の区別
3. 凍結検証、保留データ、将来面、新規アーカイブ、外部再実行
4. LLM 推論劣化
5. 継続学習と構造的忘却
6. ソフトウェア契約整合性と診断
7. 現実ドメインの支持、非支持、沈黙
8. 失敗台帳からの設計規律
9. 推定レイヤーで言えること、言えないこと

公開第二稿では、仕様固定アンカーの詳細証明は繰り返さない。第一稿の基礎座標を前提に、観測・推定指標の妥当性と追加予測力を扱う。


4. 最小形式と収支原理の扱い

`10_paper1_minimal_form.md` と `11_paper2_balance_principle.md` は、v3 編集中は現役の内部基礎分冊として保持する。公開第一稿では、その内容を基礎理論本文に統合する候補である。

統合後も、これらを削除しない。証明・厳密版の参照元、付録素材、または保管された基礎分冊として残す。物理的な移動やファイル名変更は、公開第一稿の本文構成が固まるまで行わない。

したがって、現時点では次を行わない。

- `10_paper1_minimal_form.md` の削除
- `11_paper2_balance_principle.md` の削除
- `archive/` への移動
- `02_core.md` から Paper 1 / Paper 2 への参照削除


5. 非方針

本メモでは次を行わない。

- 新しい支持判定の追加
- 既存の非支持結果の救済
- 仕様固定アンカーと推定レイヤーの支持の混同
- 公開論文タイトルの確定
- 現在の内部ファイル名の変更
- 本文で `Paper A` / `Paper B` という仮ラベルを使うこと

公開時の名前は、本文の表現に合わせて「公開第一稿」「公開第二稿」として扱う。

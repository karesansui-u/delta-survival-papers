# 投稿用集中版の設計

## 目的

このメモは、構造持続理論を外部評価に出すときの発表導線を固定するための
作業メモである。

現在の Lean 形式化リポジトリと論文リポジトリには、多数の橋渡し、
補論、実験記録、外部理論接続、監査導線が含まれている。これらは研究全体
としては重要だが、初見の評価者にすべてを同時に見せると、理論の本質より
も「広げすぎ」「名前を付けすぎ」「過剰な橋渡し」に見えやすい。

投稿用の主論文では、中心を次に絞る。

> 構造持続理論は、持続・停止・崩壊を厳密に計算可能な問題として
> 立てるための必要文法を与える。必然性定理は、同じ
> 持続・停止・崩壊計算を保存する別表現において、この文法が
> 再出現することを読む定理である。Lean 形式化版では、この定理を
> G1 としてまとめている。

主論文の目的は、構造持続理論が「広い理論である」ことを示すことではない。
持続・停止・崩壊計算の必要文法と、その少数の強い適用例を、読み手が
追える粒度で示すことである。

## 発表上の問題

現状の外部評価で起きやすい誤読は次である。

- Lean ファイル数や橋渡しの多さが先に見え、理論の必要文法が見えにくい。
- Shannon 型の比喩が前に出ると、歴史的同格主張として警戒される。
- 外部理論接続を大量に見せると、統一理論の過大主張に見える。
- 証明書、監査、公開主張の語彙が先に見えると、主張管理フレームワークに
  矮小化される。
- 実験、証拠層、橋渡しが混ざると、G1 必然性定理の数学的主張と
  実証検証の主張が混同される。

したがって、投稿用集中版では次を避ける。

- Lean モジュール数を主要な売りにしない。
- Shannon と同列である、という語りをしない。
- 外部理論接続の網羅性を主論文の中心に置かない。
- すべての橋渡しを主論文に入れない。
- 「持続・崩壊は根源的」と「この理論の到達度」を混ぜない。

持続・崩壊が根源的であることは、対象の重要性である。
必然性定理、G2/G3/G4 読取り、少数の適用例が通っていることは、
理論の到達度である。
この二つは近いが、同じではない。

## 主論文の中心主張

主論文の中心主張は三段にする。

1. **問題設定**

   「持続する」「停止する」「崩壊する」を計算可能な問題として立てるには、
   何を必ず明示しなければならないのか。

2. **必要文法**

   維持対象、必要構造、存続可能領域、損失または修復込み負担、
   有効支援、境界、時間範囲、観測・変換器・証明書を分ける。
   この分解によって、候補計算は境界読取りになり、診断、予測、
   回復、介入設計の対象になる。

3. **必然性定理（G1）**

   同じ持続・停止・崩壊計算を保存する別表現では、この文法に相当する
   役割が再出現する。したがって、この文法は単なる便利な表記ではなく、
   明示された保存条件と同値条件のもとで避けられない。

この三段を読者が理解する前に、橋渡し群、外部理論接続、広い応用一覧を
見せない。

## 推奨構成

投稿用集中版は、70--90 ページ程度を目安にする。

1. **導入**

   持続・停止・崩壊を計算可能な問題として立てるための問いを提示する。
   ここでは Shannon 型比喩や歴史的位置づけを控えめにする。

2. **必要文法**

   `F`, `K`, `V_K`, `L/B`, `R`, `M`, 境界、時間範囲、
   観測・変換器・証明書を定義する。
   特に `R` と `M` の分離を、停止・崩壊診断の要として説明する。

3. **候補計算と境界読取り**

   `S = M exp(-L)` 型の会計値は候補計算として出せるが、
   維持対象、必要構造、負担、有効支援、境界、観測根拠が揃って
   初めて正式な境界読取りになることを示す。

4. **必然性定理（G1）**

   保存条件と同値条件を「同じ計算であるための同一性条件」として説明する。
   G1 は前提なしの全宇宙的普遍性ではなく、同じ持続・停止・崩壊計算を
   扱うための必要文法を定理化するものだと明記する。

5. **G2/G3/G4**

   容量読取り、指数読取り、方策読取りを、G1 文法の上に乗る
   計算導線として最小限に説明する。
   ここでは閉じた集約点の一覧より、「何が読めるようになるか」を
   優先する。

6. **少数の適用例**

   例は増やしすぎない。候補は次のように絞る。

   - LLM 推論劣化 / 継続学習忘却のうち、仕様固定と観測が明確なもの。
   - QSA / SRE-H1 のように、生データ、測定、変換、境界読取りが
     追いやすいもの。
   - ソフトウェア仕様空間のように、維持対象と必要構造が明確なもの。

   各例は次の順序で書く。

   ```text
   入力データまたは仕様
   -> 維持対象
   -> 必要構造
   -> 損失・負担
   -> 有効支援
   -> 境界
   -> 観測・変換器・証明書
   -> 読取り
   -> 主張しないこと
   ```

7. **非主張境界**

   経験的真理、世界予測、各分野固有定理の再証明、根拠なし転用、
   無ガードの全宇宙的普遍性は外側に置く。

8. **関連研究**

   Viability theory、制御理論、信頼性工学、安全ケース、
   情報理論、大偏差理論、レジリエンス理論との関係を、最後に置く。
   ここでは「同格」を主張せず、どの役割が近く、どこが違うかだけを書く。

## 主論文に入れないもの

次は主論文の中心から外す。

- 外部理論接続の全一覧。
- すべての橋渡し台帳。
- すべての Lean module の列挙。
- 歴史的比喩の長い説明。
- 「人類初」「Shannon と同列」などの評価語。
- 未整理の広域ドメイン一覧。
- 実証層の途中記録をすべて見せること。

これらは補助資料、外部台帳、付録、リポジトリ案内に残す。

## 評価者に見せるべき最小導線

初見の評価者には、次の順序だけを見せる。

1. 短縮版: `PREPRINT_THEORY_SHORT_ja.md`
2. 投稿用集中版: この設計に従う主論文
3. Lean アーティファクト要約: `PREPRINT_LEAN_ARTIFACT_ja.md`
4. 少数の実例: LLM / QSA / SRE-H1 / 仕様空間から 2--4 本
5. 必要に応じて `persistence-lean` の theorem map

大量の橋渡しや外部理論接続は、評価者が本質を掴んだ後に見せる。

## 表現規律

使うべき表現:

- 持続・停止・崩壊を計算可能な境界問題として立てるための必要文法。
- 必然性定理。
- 同じ計算であるための保存条件と同値条件。
- 候補計算と正式な境界読取りの区別。
- 各分野の予測モデルを置き換えず、境界帰結を再現可能にする座標を与える。

避けるべき表現:

- 世界を一つの式で予測する。
- すべての分野が同じ法則で動く。
- Shannon と同等の完成度。
- Lean ファイル数がすごいから価値がある。
- 外部理論接続が多いから価値がある。

## 現在の判定

発表戦略としては、今は拡張より収束を優先する。

理論の本質は、広い橋渡し群ではなく、必然性定理と
持続・停止・崩壊計算の必要文法である。
したがって、投稿用集中版では、橋渡しを削り、G1 と少数の強い実例に
集中する。

この方針は、理論の射程を弱めるものではない。
むしろ、理論の本質を初見読者に誤読させないための発表上の制約である。

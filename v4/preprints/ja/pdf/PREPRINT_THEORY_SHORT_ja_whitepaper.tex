\PaperTitleBlock
  {構造持続理論 短縮版}
  {持続・停止・崩壊を計算可能な境界問題として立てるための必要文法}
  {2026年6月26日}

\begin{abstract}
構造持続理論は、維持したい性質・機能・状態をもつ構造について、維持・停止・崩壊・回復・介入を計算可能な境界問題として扱う、Lean 形式化された境界理論である。

それは一つの問いから始まる。

\begin{quote}
「持続する」「停止する」「崩壊する」を計算可能な問題として立てるには、何を必ず明示しなければならないのか。
\end{quote}

答えは、維持対象、必要構造、存続可能領域、損失または修復込み負担、有効支援、境界、時間範囲、観測・変換器・証明書である。

この理論の中心は、持続や崩壊を単一の「資源不足」や「弱さ」として扱わず、計算可能な境界問題へ変換するための必要文法を与えることにある。数値だけなら候補計算はできる。しかし、その数値が何の維持対象について、どの必要構造の、どの負担と有効支援から出た境界読取りなのかを明示しなければ、正式な持続・停止・崩壊の読取りにはならない。

Lean 形式化版では、この必然性定理を G1 としてまとめている。この定理は、この文法が単なる便利な記法ではなく、明示された保存条件と同値条件のもとで避けられないことを読む。したがって構造持続理論は、世界を一つの式で予測する理論ではなく、各分野の観測やモデルを再現可能な持続・停止・崩壊の境界帰結へ整える理論である。
\end{abstract}

\section{問い}\label{ux554fux3044}

多くの分野は、すでに持続や崩壊を語っている。制御理論は安定性を語り、信頼性工学は故障や冗長性を語り、運用工学はサービス目標と復旧余力を語り、生物学は恒常性や絶滅を語り、AI 安全性は推論の一貫性や方策の破綻を語る。

しかし、これらの言葉はしばしば混ざる。「壊れた」「弱い」「持続できない」「資源が足りない」「回復できない」という語の中に、維持対象、実現構造、負担、有効支援、境界、観測根拠がまとめて押し込まれる。

構造持続理論の出発点は、次の問いである。

\begin{quote}
「持続する」「停止する」「崩壊する」を計算可能な問題として立てるには、何を必ず明示しなければならないのか。
\end{quote}

この問いは、単なる表現上の整理ではない。何を維持対象としているのかを決めない限り、持続も崩壊も定義できない。何がその対象を成立させる必要構造なのかを決めない限り、どの構造が壊れたのかを言えない。どの境界を越えたら維持不能なのかを決めない限り、停止や崩壊は判定できない。

したがって、持続・停止・崩壊を厳密な計算対象にするには、対象と言葉を分ける必要がある。

\section{必要文法}\label{ux5fc5ux8981ux6587ux6cd5}

構造持続理論の基本座標は次である。

\begin{itemize}
\tightlist
\item
  $F$: 維持される性質・機能・状態・同一性・述語・目標。
\item
  $K$: $F$ を成立させる必要構造または実現構造。
\item
  $V_K$: $K$ が $F$ を成立させられる存続可能領域。
\item
  $(L,B)$: 損失または修復込みの純負担。
\item
  $R$: 名目資源または原資源。
\item
  $M$: 現在の維持対象に対して実際に効く有効支援。
\item
  境界: 維持不能、回復不能、フォールバック必要性などを読む境界。
\item
  時間範囲: どの期間や地平で読んでいるか。
\item
  観測・変換器・証明書: 候補値を正式な境界読取りとして扱うための根拠。
\end{itemize}

この文法で重要なのは、資源があることと、有効支援があることを分ける点である。予算、人員、計算資源、ログ、記憶、道具が存在しても、それが対象機能を支える $M$ に変換されていなければ、維持には効かない。

同じように、支援があっても、必要構造 $K$ がすでに存続可能領域 $V_K$ を外れていれば、その支援は機能を維持できない。逆に、構造が残っていても、損失や修復負担 $(L,B)$ が大きすぎれば、境界を越える。

このため、停止や崩壊は単一の原因ではない。少なくとも、資源側、構造側、接続側、負担側、根拠側のどこで境界が破れたのかを分けて読む必要がある。

\section{候補計算と境界読取り}\label{ux5019ux88dcux8a08ux7b97ux3068ux5883ux754cux8aadux53d6ux308a}

数値だけなら、いつでも計算できる。たとえば $M$ と $L$ を置けば、

\[
S = M \exp(-L)
\]

は計算できる。

しかし、その値が何を意味しているかは別問題である。その $M$ は本当に対象機能を支える有効支援なのか。その $L$ は本当に必要構造の損失または修復込み負担なのか。その境界は本当に維持不能や回復不能の境界なのか。その観測はどの範囲で妥当なのか。

構造持続理論は、この違いを分ける。

\begin{itemize}
\tightlist
\item
  候補計算: 変数を置けば得られる数値。
\item
  境界読取り: 維持対象、必要構造、負担、有効支援、境界、時間範囲、根拠が揃った計算。
\end{itemize}

証明書や読取り資格条件は、算術を発生させるものではない。計算値を、どの意味・どの範囲・どの読取りとして採用してよいかを決める条件である。

したがって、構造持続理論の第一層は、持続・停止・崩壊を計算可能な境界問題に変換することである。第二層は、その境界計算をどこまで正式な読取りや公開主張として使ってよいかを管理することである。

\section{必然性定理（G1）}\label{ux5fc5ux7136ux6027ux5b9aux7406g1}

Lean 形式化版では、必然性定理を G1 としてまとめている。G1 は定理本体として閉じた公開入口まで到達している。

G1 の読みは次である。

\begin{quote}
維持対象をもつ構造について、持続・停止・崩壊を厳密に計算し、維持対象、境界読取り、証明書状態を保存する別表現を許すなら、維持対象、必要構造、存続可能領域、損失・負担、有効支援、境界、変換器、証明書に相当する役割が再出現する。
\end{quote}

したがって G1 は、「この座標で見ると便利である」というだけの提案ではない。明示された保存条件と同値条件のもとで、この種の境界文法が避けられないことを示す必然性定理として読むものである。

ここでの保存条件や同値条件は、外から無理に足した条件ではない。「同じ持続・停止・崩壊の計算をしている」と言うための同一性条件である。維持対象が変わる、境界が変わる、読取りが変わる、証明書の身分が変わるなら、それは別の計算である。

G1 が固定するのは、前提なしで世界全体を説明する万能文法ではない。維持対象をもつ構造について、同じ境界計算をしていると言うために必要な文法である。

\section{予測との関係}\label{ux4e88ux6e2cux3068ux306eux95a2ux4fc2}

構造持続理論は、世界を \texttt{S\ =\ M\ exp(-L)} だけで予測する理論ではない。しかし、予測力がない理論でもない。

役割は、各分野で何を測れば、持続・停止・崩壊・回復の再現可能な帰結を読めるのかを決めることにある。

維持対象、必要構造、損失・負担、有効支援、境界、時間範囲、観測、変換器、証明書が正しく与えられていれば、同じ型の境界条件から同じ型の帰結を読める。たとえば、維持できる、崩壊する、回復不足になる、フォールバックが必要になる、どの介入でどの座標が動く、という帰結である。

この意味で、構造持続理論は各分野の予測モデルを置き換えない。各分野の観測やモデルを、再現可能な境界帰結を出す形に整える理論である。

\section{分野横断性}\label{ux5206ux91ceux6a2aux65adux6027}

構造持続理論は、物理、生物、ソフトウェア、運用、制御、組織、LLM が同じ固有法則で動くと主張しない。本家機構は分野ごとに違うままでよい。

統一するのは、持つ、止まる、壊れる、戻る、介入が効く、という読取り形式である。

どの分野でも、同じ形式で問える。

\begin{itemize}
\tightlist
\item
  何が維持されるべきか。
\item
  何がそれを成立させているか。
\item
  何が境界を押しているか。
\item
  何が有効支援として効いているか。
\item
  いつ境界を越えるか。
\item
  どの介入がどの座標を動かすか。
\end{itemize}

このため、異なる分野の現象を同じにするのではなく、違いを保ったまま、持続・停止・崩壊の読取りを比較できる。

AI や LLM では、維持対象を、与えられた前提や規則のもとで論理一貫性を保つ推論機能として置ける。未範囲づけの矛盾、時間的に未整理の更新、参照元どうしの衝突、未整理の上書きは、一貫性を保てる推論経路の集合を縮小させる。修復は、範囲分離、依存再提示、外部整理、分離された変換器、フォールバック、停止準備として表せる。

アラインメントの観点では、構造持続理論は推論を常に強く維持する理論ではない。望ましい推論一貫性や根拠つき記憶は維持対象になり得るが、長期自律計画、権限拡大、監視回避、自己保存的方策、証明書なしの外部実行などは、維持してはいけない対象として置ける。その場合の設計課題は、危険な推論構造に有効支援を与えず、境界を越えたら記憶、道具、計画範囲、外部実行、自己参照ループを隔離・停止・降格することである。

\section{現在の Lean 状態}\label{ux73feux5728ux306e-lean-ux72b6ux614b}

Lean 形式化リポジトリは \texttt{persistence-lean} である。2026年6月26日時点の安全な読みは次である。

\begin{itemize}
\tightlist
\item
  G1: 必然性定理 / 無代替性の定理本体は閉じた公開入口まで到達。
\item
  G2: 容量読取りは閉じた公開入口まで到達。
\item
  G3: 具体イベント指数読取りは閉じた公開入口まで到達。
\item
  G4: 方策本体読取りは閉じた公開入口まで到達。
\item
  運用計算可能性: 有限の生データから G2/G3/G4 読取り束への最終公開入口まで到達。
\end{itemize}

ただし、各分野固有定理の再証明、経験的予測の自動保証、測定妥当性の証明、根拠なし外部転用は、この閉じた中核の外側である。

\section{主張しないこと}\label{ux4e3bux5f35ux3057ux306aux3044ux3053ux3068}

構造持続理論は、次を主張しない。

\begin{itemize}
\tightlist
\item
  \texttt{S\ =\ M\ exp(-L)} だけで世界を予測できる。
\item
  すべての分野が同じ固有法則で動く。
\item
  現実の測定妥当性が Lean だけで保証される。
\item
  ある分野の介入効果が別分野へ自動転用される。
\item
  熱力学、制御理論、情報理論、信頼性理論などを置き換える。
\end{itemize}

主張するのは、維持対象をもつ構造について、持続・停止・崩壊・回復・介入を計算可能な境界問題として立てるための必要文法と、その文法からどの読取りが帰結するかである。

\section{結論}\label{ux7d50ux8ad6}

構造持続理論は、持続・停止・崩壊を計算可能な境界問題として立てるための必要文法を与える。必然性定理は、明示された保存条件と同値条件のもとで、その文法が単なる便利な表記ではなく避けられないことを読む。Lean 形式化版では、この定理を G1 としてまとめている。

この理論が直接に固定するのは、世界全体の予測式ではなく、維持対象をもつ構造について持続・停止・崩壊計算を成立させるために必要な役割構造である。経験的予測、測定妥当性、各分野固有定理は別層に残る。

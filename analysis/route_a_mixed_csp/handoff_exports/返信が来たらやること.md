# 返信が来たらやること

このフォルダに外部実行者から返送が来たら、まずこの順で確認する。

## 1. 返送ファイルを分けて置く

実行者ごとに別フォルダを作る。

例:

```text
outside-rerun-1/
outside-rerun-2/
outside-rerun-3/
```

各フォルダに、返送された次のファイルを入れる。

1. `mixed_csp_primary_external.jsonl`
2. `mixed_csp_primary_external_results.json`
3. `mixed_csp_primary_external_summary.md`
4. `実行環境メモ_テンプレート.md` を埋めたもの

## 2. 最低限そろっているか確認する

次の 4 つがあるかを見る。

1. JSONL
2. results JSON
3. summary MD
4. 実行環境メモ

足りないものがあれば、その実行者には追加返送を依頼する。

## 3. ハッシュと行数を取る

各 `outside-rerun-*` フォルダ内で次を実行する。

```bash
shasum -a 256 mixed_csp_primary_external.jsonl
shasum -a 256 mixed_csp_primary_external_results.json
shasum -a 256 mixed_csp_primary_external_summary.md
wc -l mixed_csp_primary_external.jsonl
```

## 4. 支持フラグを確認する

次を実行する。

```bash
jq '.support' mixed_csp_primary_external_results.json
```

見る項目はこの 4 つだけ。

1. `primary_supported`
2. `strong_support`
3. `theory_pure_support`
4. `encoding_guardrail_passed`

## 5. 一言の結論を決める

判定は相手の感想ではなく、`support` の 4 項目で決める。

- 4 つすべて `true`
  - `4つの支持フラグがすべて true だったので再現した`
- 1 つでも `false`
  - `4つの支持フラグのうち少なくとも1つが false だったので再現しなかった`

## 6. G7 レポートに写す

次のテンプレートを埋める。

`analysis/route_a_mixed_csp/mixed_csp_g7_replication_report_template.md`

最低限埋める場所:

1. package identity
2. outside-group environment note
3. returned artifacts
4. frozen-design compliance
5. core reproduction checks
6. quantitative summary
7. interpretation
8. one-line program update

## 7. 成功したらどうなるか

1 人成功だけでも、outside-project rerun の前進になる。

2〜3 人が同じ bundle で、4 つの支持フラグをすべて `true` で返したら、
Mixed-CSP は

```text
project-side reproducibility
```

から

```text
contracted outside-project rerun support
```

へ一段上がる。

これは

1. Route A の外部再現性が強くなる
2. G7 を実データで前に進められる
3. 「自分の環境でしか出ない結果ではない」とかなり言いやすくなる

という意味がある。

ただし、これだけで Exp43c や observational branches まで全部閉じるわけ
ではない。

## 8. 失敗したらどうするか

1. informal rescue はしない
2. どの support flag が落ちたかを記録する
3. 環境差分か、bundle 問題か、実行ミスかを切り分ける
4. 必要なら dedicated replication-failure note を切る
